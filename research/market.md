# Market: what people search, complain about, and want

**Bottom line:** People don't want more AI docs. They want shorter, correct docs that answer "why should I care, and how do I run it". Every tool I checked generates text, and some lint style. None of them combines reader targeting, a length budget, verification against code, and a lint pass. A one-page cram sheet with honest cut reporting is not offered by anyone.

Method: web search, the Hacker News Algolia API, and vendor pages. Reddit, X, and LinkedIn were blocked or behind logins, so this skews toward HN and blogs. Ranking is by how many distinct sources I saw. It is a rough frequency count, not a survey.

## 4. Existing tools and the gap
| Tool | What it does | Reader target | Length cap | Checks code | Style lint |
|---|---|---|---|---|---|
| [Mintlify agent](https://www.mintlify.com/blog/agents-launch.md) | Drafts and updates docs from prompts and PRs | – | – | – | Vale in CI |
| [ReadMe AI](https://readme.com/ai) | PR-driven updates, AI linting, docs audit | – | – | – | ✓ |
| [Swimm](https://swimm.io) | Code-coupled docs; now legacy modernization | – | – | ✓ (code mapping) | – |
| [Docusaurus](https://docusaurus.io/docs) | Static site generator, no AI | – | – | – | – |
| GitBook AI, DeepWiki | Could not fetch (404 / 429) | ? | ? | ? | ? |
| [Vale](https://vale.sh) | Prose linter with YAML rules | – | – | – | ✓ |
| [Anthropic doc-coauthoring](https://github.com/anthropics/skills/blob/main/skills/doc-coauthoring/SKILL.md) | Interview → draft → reader test with a sub-agent | ✓ | – | – | – |
| [humanizer skill](https://github.com/blader/humanizer) | Rewrites away Wikipedia AI patterns | partial | – | – | rewrite only |
| [awesome-claude-skills](https://github.com/travisvn/awesome-claude-skills) | No docs-writing skill listed | | | | |

**Gap:** No tool puts all four in one loop: a reader card, a word budget, claims tied to `file:line`, and a lint gate. None offers a budgeted one-page cram sheet that reports what was cut. `clean-docs` covers that.

## 5. Cheat sheets: useful vs unreadable
| Useful | Unreadable |
|---|---|
| Narrow scope, common cases first ([HN](https://news.ycombinator.com/item?id=9829104)) | Everything included: a full reference shrunk to 6pt |
| One printable page ([HN vi sheet](https://news.ycombinator.com/item?id=991295)) | Someone else's dense exam sheet ([HN](https://news.ycombinator.com/item?id=9836347)) |
| A diagram for confusing architecture ([HN](https://news.ycombinator.com/item?id=9967207)) | Commands with no "why", which leads to cargo-culting ([HN](https://news.ycombinator.com/item?id=9913617)) |
| Expression/Description tables, sections by topic ([devhints](https://devhints.io/bash)) | Long prose, no grouping |
